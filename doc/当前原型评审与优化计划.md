# 当前原型评审与优化计划

更新时间：2026-07-03

适用范围：

- 原型工程：`prototype/auris-flow-ui`
- 主设计文档：`设计文档.md`
- UI 设计文档：`UI设计文档.md`
- Agentic 设计文档：`Agentic智能化设计文档.md`

## 1. 结论

当前原型已经从单一的“调听证据工作台”演进为一个完整的 Agentic 音频质检与数据资产平台。它包含运营首页、租户、项目、任务配置、数据管理、知识库、调听、标签生产治理、业务洞察、评测中心、数据资产和设置等模块。

因此，后续不应继续只按截图反馈修局部 UI。当前主要风险不是单个按钮或单个图表，而是：

1. 交互语义不统一；
2. 页面之间的证据链、资产链、任务链没有完全对齐；
3. Dagster、模型服务、Audio Intelligence Service 等底层能力的暴露层级不稳定；
4. 标签治理、评测、发布门禁和 Human Loop 已经形成复杂闭环，但文档没有完全同步；
5. 原型工程开始变成超大单文件，继续叠加会降低调整速度和一致性。

本轮应先更新设计文档，再按统一交互契约继续重构原型。

## 2. 当前原型基线

当前原型的产品基线可以定义为：

面向汽车门店销售质检场景的多租户 Agentic 音频数据资产平台。平台通过任务配置接入多平台数据，通过音频智能服务处理 VAD、Diar、ASR 和噪音等音频能力，通过标签生产治理台持续优化标签、Prompt、评测和发布门禁，通过调听工作台完成证据审查、串音排查、说话人标注和业务单据关联，通过数据资产和业务洞察形成可回溯、可回填、可评测的数据闭环。

当前原型已经覆盖的核心模块：

| 模块 | 当前定位 | 主要风险 |
| --- | --- | --- |
| 运营首页 | 展示项目运行、异常任务和趋势入口 | KPI、趋势和待处理之间的跳转语义需要统一 |
| 租户管理 | 多租户隔离、配额、成员和审计 | 按钮状态、配额调整和项目下钻需要明确反馈 |
| 项目管理 | 项目容器、成员、标签版本、质量目标 | 项目创建不能和数据接入混淆 |
| 任务配置 | 数据流程编排、模型服务绑定、调度、A/B、输出资产 | 业务流程与 Dagster 映射需要分层表达 |
| 数据管理 | 时间、空间、事件、人物、单据聚合 | 聚合层级、排序和展开需要更稳定的交互模型 |
| 知识库 | 知识源、索引、实体、消费路径 | 知识可视化还应进一步图谱化 |
| 调听工作台 | 简单调听、证据审查、串音矩阵 | 标签、Minimap、ASR、单据、Agent 建议之间需要统一证据上下文 |
| 标签生产治理台 | 智能抽取、Prompt 优化、效果评价、发布门禁 | 闭环已经复杂，需要统一运行详情模型 |
| 业务洞察 | 趋势、归因、指标下钻和报告 | 不同 tab 需要更强差异化，避免图表近似 |
| 评测中心 | 模型、Prompt、标签、badcase 评测 | 需要和标签治理共享样本、Trace、版本和门禁 |
| 数据资产 | 目录、详情、血缘、回填、质量、任务 | 资产血缘应图优先，避免列表和图重复 |
| 设置 | 模型、工具、阈值、权限、存储、通知 | 设置项需要更像可操作配置，不只是静态列表 |

## 3. 需要先固化的交互契约

### 3.1 点击语义

所有可点击元素必须落入以下一种语义，不允许同一类卡片在不同页面产生不同效果。

| 语义 | 行为 | 典型控件 | 验收 |
| --- | --- | --- | --- |
| 聚焦 | 不跳转，只更新当前页选中对象、右侧详情、图表高亮 | 指标卡、图例、趋势点、证据片段、候选标签 | URL 和模块不变，局部状态变化明显 |
| 下钻 | 进入另一个模块或另一层详情 | 下钻证据、进入调听、查看资产血缘 | 按钮文案必须明确目标 |
| 生成候选 | 由 Agent 或规则生成候选对象 | 生成标签候选、生成映射建议、生成运行草稿 | 只写候选或草稿，不覆盖线上 |
| 人工修改 | 人修改候选、标签、说话人、规则、Prompt | 保存标注、修改候选、接受当前 | 必须记录修改前后和修改人 |
| 写回/回填 | 把结果写入数据资产或外部平台 | 同步输出资产、创建回填、导出回写 | 必须展示影响范围和审批状态 |
| 发布 | 发布标签版本、Prompt 版本、任务版本 | 发布版本、灰度发布 | 必须经过门禁，不允许直接覆盖 |
| 诊断 | 展示底层映射、Trace、RunRequest、AssetCheck | 高级执行映射、Trace、运行记录 | 默认不作为业务主语言 |

### 3.2 跳转原则

- 普通卡片点击默认只能聚焦，不允许隐式跳模块。
- 只有带明确动词和目标的按钮才能跳转，例如“下钻证据”“进入调听”“查看资产血缘”。
- 趋势图、桑吉图、雷达图、血缘图的节点点击默认聚焦并更新右侧解释；跳转必须通过右侧动作按钮完成。
- 任何 Agent 建议不能直接变成线上结果，只能进入候选、ChangeSet、Human Loop 或评测运行。

### 3.3 状态反馈

所有按钮都必须产生至少一种反馈：

- 更新选中状态；
- 更新右侧详情；
- 追加运行记录；
- 显示 action feedback；
- 改变状态 chip；
- 打开抽屉、弹窗或确认面板；
- 禁用发布按钮并解释阻断原因。

无反馈按钮应删除、降级为文本说明，或合并到更明确的动作入口。

## 4. 产品抽象需要收敛

### 4.1 事件关联

汽车业务里的试驾单、报价单、订单、合同、金融分期单、保险单、交付单、售后工单，不应作为孤立附件处理。它们应统一抽象为“事件关联对象”。

事件关联对象需要能和以下对象建立关系：

- 音频片段；
- ASR 句子；
- VAD / Diar 片段；
- 销售、客户、设备、门店；
- 业务事件；
- 标签；
- 单据字段；
- Agent 建议；
- 数据资产。

在 UI 上，事件关联必须同时出现在：

- 调听 Minimap；
- 证据审查轨道；
- ASR 句子详情；
- 右侧单据/字段差异；
- 数据资产血缘；
- 洞察下钻。

### 4.2 Audio Intelligence Service

ASR 不应被画成单点“转写服务”。正确抽象是 Audio Intelligence Service。

该服务内部能力包括：

- VAD；
- Diar；
- ASR；
- 语言识别；
- 噪音/音乐/静音检测；
- 串音候选特征；
- 置信度和质量评分。

服务应通过 provider 参数切换：

- 阿里；
- 火山；
- 自研；
- 开源。

原型中必须让用户看到：

- 当前 provider；
- 服务版本；
- 各能力开关；
- 关键参数；
- 成本、延迟、错误率；
- 对标签、评测和资产生成的影响；
- 失败后是否进入 Human Loop 或回填任务。

### 4.3 标签优化运行

标签治理不是单纯的标签 CRUD。当前原型应统一为“标签优化运行”。

主线：

输入范围 -> Agent 智能抽取/优化 -> 人工修改/确认 -> 效果评价 -> 自动化等级判断 -> Dagster 执行/回写 -> 发布/回流

关键对象：

- LabelTaxonomy；
- LabelVersion；
- LabelCandidate；
- PromptAsset；
- PromptVersion；
- ExtractionRun；
- EvalDataset；
- EvalRun；
- ChangeSet；
- HumanReviewTask；
- ReleaseGate；
- DagsterRunDraft；
- TraceRef。

### 4.4 数据资产血缘

数据资产页必须图优先。列表只做目录和详情，不承担血缘表达。

血缘图至少区分：

- SourceAsset；
- Asset；
- AssetCheck；
- Backfill；
- Human Loop；
- External Callback；
- Report / Insight。

节点点击默认聚焦详情，跳转必须通过明确动作。

## 5. 模块级优化计划

### 5.1 调听工作台

目标：从“密集堆叠页面”升级为“音频证据操作台”。

必须优化：

- 简单调听、证据审查、串音矩阵共享同一个当前会话和证据上下文。
- 说话人标注采用类聊天布局，左侧默认坐席/销售，右侧客户。
- 支持 spk 选择、声道选择、说话人置信度、音乐/噪音/静音/串音标签。
- 标签轨支持 L 层级、隐藏、创建、拖动开始/结束、重叠自动分层。
- 单据事件进入轨道，并和 Minimap、ASR、右侧字段差异联动。
- Agent 建议区展示原因、证据、置信度、影响范围和可执行动作。

### 5.2 标签生产治理台

目标：从“标签管理页面”升级为“标签优化闭环台”。

必须优化：

- 标签四层结构固定为：标签域 -> 标签组 -> 标签 -> 标签值/动作。
- 首屏展示闭环阶段：输入、Agent 提升、人工修改、效果评价、自动化等级、Dagster 执行。
- 效果评价和发布门禁共享同一个 LabelOptimizationRun。
- 每个候选标签展示来源证据、Prompt 版本、模型版本、Trace、置信度、冲突原因、人审状态、影响资产。
- Prompt 优化包含系统指令、标签定义、正例、负例、输出 JSON Schema、冲突规则、后处理规则。
- A/B 和影子评测只改 run_tags，不覆盖生产数据。

### 5.3 任务配置

目标：从“工程画布”收敛为“数据流程编排配置”。

必须优化：

- 任务类型不能写死成“登录风险复核”，应抽象为可复用流程模板。
- 标准流程模板包括：多平台关联接入、音频智能处理、标签抽取、证据生成、资产导出回写。
- 主语言使用业务词：数据源、处理步骤、输出资产、调度、实验、回写。
- 诊断层再展示底层映射：JobDefinition、AssetSelection、PartitionsDefinition、RunRequest、AssetMaterialization、AssetCheck。
- 节点拖拽时连线必须跟随；新增节点必须可配置输入、处理、输出和执行映射。

### 5.4 数据资产

目标：从“资产信息页”升级为“资产血缘与回填工作台”。

必须优化：

- 资产血缘 tab 默认展示图。
- 资产详情、血缘、回填、质量、资产任务应共享当前资产上下文，避免重复。
- 回填必须展示影响范围、审批、下游重算、失败分区和 RunRequest 草稿。
- 资产任务必须展示生成记录、运行状态、失败分区、可重跑操作。

### 5.5 业务洞察

目标：从“图表集合”升级为“洞察到证据链下钻”。

必须优化：

- 不同 tab 图表必须差异化：趋势、桑吉、雷达、漏斗、报告列表不能近似。
- 趋势图展示当前值、变化、目标线、事件标记、拉升/拖累、下一步动作。
- 点击图例或点只聚焦；下钻证据必须通过明确按钮。
- 洞察结论必须能回到调听、标签、资产和评测样本。

### 5.6 设置

目标：从“静态配置列表”升级为“模型、服务和策略接入中心”。

必须优化：

- 模型配置展示 Audio Intelligence Service、Tagger、LLM、Embedding 的 provider、版本、路由和降级策略。
- 工具配置展示工具 Schema、超时、权限、副作用和成本。
- 阈值配置展示低置信、串音、标签、门禁、回填审批阈值。
- 权限配置展示角色、租户、项目、数据范围和高风险动作审批。
- 账号设置应有类似 ChatGPT 的用户菜单和可操作模态框。

## 6. 工程结构建议

当前原型主文件已经过大，继续增加页面会使维护成本上升。下一阶段建议先做轻量拆分，不改变交互效果。

建议拆分：

- `src/data/`：mock 数据、枚举、标签体系、任务模板、资产样本；
- `src/components/common/`：Panel、MetricCard、ActionRail、EvidenceLink、StatusChip；
- `src/components/charts/`：TrendChart、RadarChart、SankeyLite、LineageGraph；
- `src/modules/listening/`：调听相关视图；
- `src/modules/labels/`：标签治理相关视图；
- `src/modules/tasks/`：任务配置相关视图；
- `src/modules/assets/`：数据资产相关视图；
- `src/modules/insights/`：业务洞察相关视图。

样式建议拆分：

- `tokens.css`；
- `layout.css`；
- `components.css`；
- `modules/listening.css`；
- `modules/labels.css`；
- `modules/tasks.css`；
- `modules/assets.css`；
- `modules/insights.css`。

## 7. 验收标准

### 7.1 全局验收

- 1440x1024 下无横向溢出、无遮挡、无大块空白。
- 浅色、深色、高对比主题下核心文字和状态颜色对比度足够。
- 所有按钮都有可见反馈。
- 普通卡片不隐式跳转，跳转按钮必须有明确目标。
- 同一业务对象在不同模块中的 ID、版本、状态一致。
- 业务层不直接暴露 Dagster / DAG / mock 等技术词，除非在高级执行映射中。

### 7.2 调听验收

- 简单调听能修改说话人、声道、实体标签、意图标签、质检标签。
- 证据审查能创建 L 层级标签、隐藏轨道、拖动标签块、重叠自动分层。
- 串音矩阵能选择单元并回到证据审查。
- 单据事件在 Minimap 和标签轨上可见，并能关联到 ASR 证据。

### 7.3 标签治理验收

- 输入范围改变后，Agent 建议、候选标签、评测配置和 Dagster 草稿同步变化。
- Agent 建议和人工修改能在 ChangeSet 中区分。
- 效果评价和发布门禁使用同一个运行上下文。
- 未通过门禁时发布按钮禁用，并给出阻断项和下一步动作。

### 7.4 任务和资产验收

- 任务节点拖拽时连线跟随。
- 新增节点能配置输入、处理、输出和执行映射。
- 数据资产血缘以图为主，节点点击聚焦，动作按钮下钻。
- 回填展示影响范围、审批状态和下游重算。

## 10. 后端设计准备阶段

当前原型已经基本完成第一轮交互闭环补齐，后续进入后端开发设计准备阶段。后端第一阶段不追求实现全部高级诊断能力，而是先支撑当前原型可见主流程：上下文、权限、连接器、任务运行、音频证据、知识库、标签、评测、洞察、资产和设置。

### 10.1 后端技术基线

后端基线固定为：

- FastAPI BFF；
- MySQL；
- Redis；
- MinIO / OBS / S3；
- Dagster；
- Qdrant；
- OpenTelemetry。

不使用 ClickHouse。洞察、运营大盘和报告中心第一阶段使用 MySQL 聚合表、预计算结果、Redis 缓存和 Qdrant 召回解释。

### 10.2 后端开发顺序

1. 上下文与权限：统一 `tenant_id`、`project_id`、`user_id`、`store_id`、`date`、`model_version`、`label_version`，所有接口必须带上下文校验。
2. MySQL 核心资源 API：租户、项目、连接器、任务、资产、音频、标签、评测和设置。
3. 异步运行系统：task runs、agent runs、eval runs、exports、backfills、external callbacks，统一状态为 pending、running、success、failed、blocked、cancelled。
4. 调听证据链：audio session、conversation boundary、tracks、event links、evidence packs、human review decisions。
5. Qdrant 知识库索引：knowledge source、chunk、embedding、recall、quality gate、effect metrics。
6. 洞察与效果：MySQL 聚合 + Qdrant 召回解释，支撑趋势、桑吉、漏斗、雷达、报告和证据下钻。
7. 外部回写：处理后 WAV 上传 OBS / S3 后回传 URL，标签结果回调，复核结论回调，证据包导出，失败队列和重试审计。

### 10.3 后端资源优先级

第一批必须实现：

### 10.4 MySQL 与 Qdrant 边界

MySQL 保存权威业务状态，包括租户、项目、连接器、任务、音频会话、边界、标签、评测、资产、知识源元数据、运行状态、人审任务、审计和外部回写回执。

Qdrant 只保存用于召回的向量和 payload，不保存审批、发布、权限或最终业务状态。Qdrant payload 必须带可回跳字段：tenant_id、project_id、source_id、asset_key、trace_id、version、evidence_id、label_version。

前端不直接访问 Qdrant。知识库、标签候选、洞察解释、相似证据和 badcase 召回都通过 BFF API 返回。

### 10.5 后端验收标准

- 所有列表接口可分页、可筛选、可排序。
- 所有写操作可审计、可追踪、可重试或可解释阻断原因。
- 所有异步任务可查看运行记录、错误、重试次数、影响对象和 trace_id。
- 所有核心运行可回放：必须能通过 trace_id、run_id、partition_key、输入快照和版本号重建当时的执行上下文。
- 所有发布、回填、外部回写和高风险配置可回滚：必须保留上一版本、回滚影响范围、审批人和审计回执。
- 所有导出、回填、发布和外部回写必须有幂等键、失败队列和审计记录。
- 所有证据链对象可从洞察、标签、资产、数据管理回跳到调听证据。
- 所有 Agent 输出只能写候选、草稿、人审任务、评测运行或回填草稿，不能直接覆盖线上结果。
- 所有对象必须按 tenant/project 隔离，禁止跨租户读取。
