# Agentic 音频平台 UI 设计文档

## 1. 文档定位

本文档从《设计文档.md》中抽取 UI、交互、页面结构与前端实现相关内容，作为独立的产品 UI 设计文档。

本文档只描述用户可见的信息架构、页面布局、核心工作流、交互规则、组件能力与 MVP UI 范围。底层 Dagster、Temporal、dbt、模型服务、存储与数据引擎在普通业务视图中不前置展示，在任务配置、模型服务配置、运行诊断、资产回填和开发/架构视图中按角色渐进披露。

平台 UI 采用“双层表达”：

- 业务层：面向运营、调听、标注、评测人员，不暴露 Dagster、Asset、Materialization、Partition、Backfill、Run 等底层术语。
- 配置层：面向项目管理员、平台运营、模型团队和工程团队，允许展示 Dagster Job / Op / Asset Key / IO Manager / Partition / Deps 等映射，但必须放在任务配置、模型配置、运行诊断或开发视图中，不能把底层术语作为业务主语言。

业务层统一使用以下产品语言：

- 数据资产
- 资产任务
- 数据回填
- 资产血缘
- 质量校验
- 处理轨迹
- 评测报告
- 模型对比

当前交互基准以 `prototype/auris-flow-ui` 的现有原型为准。它比早期“数据画布 / 任务画布 / 资产画布”设计稿更符合主要意图：任务配置页不是通用流程图，而是当前任务版本的编排配置中心，负责管理任务类型、画布版本、输入输出、调度、A/B 实验、模型服务绑定、输出资产和外部接口回写。

## 2. UI 设计目标

平台 UI 的核心目标是让用户围绕同一组连续业务上下文完成数据查看、调听、标注、评测、回流和洞察。

核心上下文包括：

- 租户
- 项目
- 时间
- 地点
- 人物 / 声纹
- 音频
- 事件
- 标签
- 业务单据
- 事件关联
- 模型版本
- 标签版本
- 数据资产版本

UI 必须优先支持以下任务：

- 快速找到有价值或异常的音频片段。
- 在同一时间轴内查看波形、VAD、ASR、说话人、事件、标签和人工标注。
- 在汽车等业务流程场景中，把试驾单、报价单、订单、保险单、交付单、售后工单等单据和音频事件关联起来。
- 高效完成边界修正、标签修正、声纹确认和人工复核。
- 从洞察指标下钻到原始证据。
- 从评测结果回流到 badcase、数据资产和模型优化。
- 在任务配置中清晰区分数据源接入、任务类型画布、任务版本、运行调度、实验流量、输出资产和外部系统回写。
- 在租户和项目维度下保持权限、数据和操作隔离。

## 9. 任务配置与画布能力

画布不作为一级导航和独立业务对象出现，而是作为配置能力嵌入到数据接入、任务配置和资产血缘中。用户进入时看到的是“数据源怎么导入”“任务怎么运行”“资产怎么生成”，不是先选择一个抽象画布。

平台保留三类画布能力：

- 数据接入画布：位于项目 / 数据源与连接器，用于把外部数据导入平台实体和输入引用。
- 任务类型画布：位于任务配置，用于管理任务类型、画布版本、任务版本、调度、A/B 实验、模型服务绑定和输出回写。
- 数据资产血缘视图：位于数据资产，用于查看资产生成链路、质量状态和回填影响。

### 9.1 数据接入画布

目标：配置外部数据如何进入项目，并映射成平台实体。

数据源包括：

- OBS / MinIO / S3
- 数据库
- API
- CRM
- 门店系统
- 汽车 DMS / Dealer Management System
- 试驾系统
- 订单系统
- 保险系统
- 售后工单系统
- 工牌设备
- 上传文件
- 人工标注系统
- 业务事件系统

节点类型：

- 数据源节点：OBS、API、数据库、上传文件。
- 解析节点：解析音频、JSON、CSV、日志、接口返回。
- 字段映射节点：映射到时间、地点、人物、音频、事件、标签、业务单据。
- 关联节点：通过 `store_id + time_range + device_id + customer_id + vehicle_id + document_no` 关联多源数据。
- 校验节点：校验字段完整性、时间连续性、地点合法性、单据状态合法性。
- 写入节点：写入平台实体库和数据资产。

节点配置抽屉：

- 基础信息
- 连接参数
- 字段映射
- 样例预览
- 校验规则
- 输出 Schema
- 运行历史
- 错误日志

字段映射支持：

- 拖拽映射
- 自动推荐
- 字段类型校验
- 缺失字段提醒
- 样例数据预览

### 9.2 任务类型画布

目标：配置单条或批量音频的处理流程，并把流程固化为可发布、可调度、可回滚的任务版本。

典型流程：

```text
Audio Input
  ↓
Preprocess
  ↓
VAD
  ↓
ASR
  ↓
Diarization
  ↓
Voiceprint Linking
  ↓
Boundary Detection
  ↓
Merge / Split Decision
  ↓
Tagging
  ↓
Conflict Resolver
  ↓
Confidence Gate
  ↓
Human Review
  ↓
Insight Generation
  ↓
Evaluation
```

节点类型：

- 输入节点：CRM、API、S3 / OBS、PBX、DMS、上传文件。
- 模型节点：ASR、VAD、Diarization、声纹、LLM Tagger。
- 规则节点：阈值规则、标签规则、冲突规则。
- Agent 节点：Boundary Agent、Tagging Agent、Conflict Resolver Agent。
- 人工节点：人工复核、人工标注、人工仲裁。
- 评测节点：自动化评测、抽样评测、人工评测。
- 输出节点：生成标签结果、接待记录、评测任务、数据资产、外部回写、处理后 WAV 上传和 URL 回调。

任务类型画布必须支持：

- 一个任务类型下多个画布版本。
- 生产、灰度、影子评测、热修复和 A/B 实验。
- 运行一次、设置定时、发布版本、回滚版本的明确区分。
- Dagster 映射作为配置/诊断信息展示。

节点状态：

- 未配置
- 已配置
- 运行中
- 成功
- 低置信
- 失败
- 等待人工
- 已跳过
- 已重跑

### 9.3 数据资产血缘视图

## 10. 数据管理

### 10.1 页面目标

数据管理页用于围绕时间、地点、人物、音频、事件、标签、业务单据组织所有数据对象。

核心业务对象不是单个音频，而是：

```text
同一时间 + 同一地点 + 相关人物 + 多条音频 + 多个事件 + 多个标签 + 相关业务单据
```

### 10.2 首页布局

三栏式布局：

- 左栏：维度筛选、聚合维度、保存视图。
- 中栏：分层数据列表 / 时间轴。
- 右栏：实体摘要 / 关联关系。

### 10.3 数据列表排序、聚合与层级展开

数据管理页不能只是平铺音频列表，必须支持按时间、空间、事件、人物四个主维度排序、聚合和层级展开。

主维度：

- 时间：日期、小时、分钟、接待时间窗、业务流程阶段。
- 空间：区域、城市、门店、楼层、柜台、设备、试驾车。
- 事件：接待、试驾、报价、异议、成交、离店、交付、售后。
- 人物：销售、客户、未知声纹簇、工牌、标注员。
- 单据：试驾单、报价单、订单 / 合同、保险单、交付单、维修工单。

视图模式：

- 按时间展开：日期 → 小时 → 时间窗 → 接待事件 → 音频片段。
- 按空间展开：区域 → 城市 → 门店 → 柜台 / 设备 → 销售 → 音频片段。
- 按事件展开：事件类型 → 事件状态 → 客户组 → 音频片段 → 标签 / 单据。
- 按人物展开：销售 → 客户组 → 接待事件 → 音频片段 → 单据。
- 按单据展开：单据类型 → 单据状态 → 客户 / 车辆 → 关联事件 → 音频片段。
- 按串音排查展开：门店 → 时间窗 → 多设备重叠录音 → 主录音 / 串音候选。

### 11.3 全天时空音频 Minimap

全天时空音频 Minimap 是调听页的全局导航层，展示当前项目上下文内某一天、同一门店、不同销售和不同收声设备的完整音频分布。

它的核心业务价值是解决相邻收声设备串音问题。

串音问题指：

- 销售 A 的工牌收到了销售 B 正在接待客户的声音。
- 展厅公共麦克风同时收到了多个销售的接待。
- 相邻柜台或试驾车附近的录音设备捕获了同一段对话。
- 一段接待被多个设备重复收录，导致系统误判为多个客户组。
- 串音片段被错误打上销售、客户、事件、标签或单据关联。

核心目标：

- 让用户知道当前片段处在当天接待流程的哪个位置。
- 快速发现同一天、同门店、同时间窗内不同销售和不同设备的重叠录音。
- 判断某段声音是主录音、串音、背景音还是重复收录。
- 快速发现录音空洞、异常高密度、长静音、低置信聚集点。
- 在汽车场景中快速定位试驾、报价、签约、交付等业务事件附近的录音。
- 支持从全局一天缩略图跳转到局部精细调听和标注。

展示维度：

- 时间轴：`00:00 - 24:00`。
- 空间泳道：门店、楼层、柜台、试驾车、交付区、售后区。
- 设备泳道：工牌、展厅麦克风、试驾车录音设备、电话录音。
- 销售泳道：同一门店下的不同销售。
- 人物泳道：销售、客户、未知声纹簇。
- 事件层：接待、试驾、报价、异议、成交、离店、交付、售后。
- 单据层：试驾单、报价单、订单、保险单、交付单、工单。
- 串音层：疑似串音、重复收录、跨设备同声、主录音候选。
- 质量层：低置信、边界冲突、标签冲突、单据不一致、缺失录音。

视觉表达：

- 音频存在：连续色块。
- 有效语音密度：色块深浅。
- 静音 / 无效录音：浅色或空心段。
- 当前播放点：垂直播放线。
- 当前精修窗口：可拖拽框选区域。
- 异常点：小标记点。
- 单据事件：单据图标或短标签。
- 同一客户组 / 同一订单链路：连线或同色标记。
- 疑似串音：在多个销售 / 设备泳道之间使用虚线连接。
- 主录音候选：更高亮的边框。
- 串音候选：半透明或斜纹标记。

交互：

- 点击任意时间点：跳转局部波形到该时间。
- 拖拽框选时间段：加载该时间段内所有相关音频。
- 横向缩放：从一天缩到小时 / 分钟。
- 切换泳道：按地点、设备、人员、车辆、单据分组。
- 切换串音视图：只显示同门店不同销售 / 设备的重叠录音。
- 点击事件标记：展开相关音频、标签、单据。
- 点击缺口：查看是否存在缺失录音或未接入设备。
- 点击低置信聚集点：进入低置信优先调听。
- 点击串音标记：同步播放多路录音并对齐 ASR、声纹、能量峰。
- 标记主录音：指定当前接待应归属的销售、设备和客户组。
- 标记为串音：从客户组、标签、单据关联和评测样本中降权或排除。
- 标记为重复收录：合并证据链但避免重复计数。
- 点击单据标记：打开单据侧栏并定位相关音频。
- 拖动当前精修窗口：同步更新下方多轨时间轴。
- 框选后加入上下文篮、评测集或 badcase。

Minimap 不替代下方精细时间轴。Minimap 负责一天级全局定位，下方多轨时间轴负责片段级调听、标注和边界修正。

串音判定参考信号：

- 多设备录音时间高度重叠。
- ASR 文本高度相似。
- 同一声纹在多个设备同时出现。
- 一个设备中目标销售声音较弱，但另一路设备中声音更清晰。
- 两路音频能量峰同步。
- 事件标签和单据实体高度一致。
- 门店空间上设备相邻。

模型配置页负责“服务接入”，不负责编辑某个任务类型画布。任务类型画布中的模型节点只选择服务版本、输入资产、输出资产和降级策略。

ASR 服务接入必须单独成块展示：

- 服务标识：如 `asr-whisper-prod-v2`。
- Endpoint：如 `POST /model-gateway/asr/transcriptions`。
- Auth / 租户隔离：服务调用必须携带租户、项目、任务版本和权限上下文。
- 输入契约：`audio_asset_key`、`segments_asset_key`、`speaker_asset_key`、`hotword_pack_version_id`、`language`、`return_word_timestamps`。旧 `hotwords_ref` 仅保留历史读取兼容，新写入不再接受。
- 输出契约：`transcript_asset`、`transcript_segments`、`word_timestamps`、`asr_quality`。
- Dagster 映射：`ModelService`、`Asset Key`、`IO Manager`、`Deps`、`Partition`。
- 降级策略：超时、低置信、服务不可用时选择备用 ASR 或转人工。

ASR 和说话人分离不能混成一个节点：

- ASR 节点只负责转写，主输出是 `transcript_asset` 和 `transcript_segments`。
- Diarization 节点只负责说话人分离，主输出是 `speaker_turns`。
- `speaker_transcript_view` 是派生视图，通过 `transcript_segments` 与 `speaker_turns` 时间重叠关系生成。
- 任务配置工作台右侧抽屉可以展示三者的依赖关系，但不能让用户误以为 ASR 服务本身产出最终说话人身份。

数据导出和外部服务回写属于输出节点配置，而不是 ASR 服务配置。典型输出包括：

- 处理后的 WAV 上传 OBS / S3，并生成可回传平台的访问 URL。
- 标签结果、证据包、复核结论通过接口回写业务平台。
- 回写节点需要配置 Endpoint、鉴权、重试、幂等键、失败告警和运行记录。

## 19. 体验系统：皮肤、语言、动效与智能视觉

### 19.1 多皮肤设计

平台需要支持多种皮肤，但皮肤不能改变核心信息层级和操作路径。

推荐内置皮肤：

- 专业浅色：默认运营工作台，适合日常数据管理、标注和评测。
- 专业深色：适合长时间调听、夜间质检和大屏监控。
- 高对比模式：适合审计、质检和弱视用户。
- 粒子数据风：适合洞察、Agentic 任务追踪、Minimap、空状态和演示场景。

皮肤系统应基于设计 Token：

- `color.background`
- `color.surface`
- `color.text`
- `color.border`
- `color.primary`
- `color.success`
- `color.warning`
- `color.danger`
- `color.lowConfidence`
- `color.crosstalk`
- `color.document`
- `color.agent`
- `radius`
- `shadow`
- `motion.duration`
- `motion.easing`

皮肤切换要求：

- 用户级偏好保存。
- 项目级默认皮肤可配置。
- 支持跟随系统浅色 / 深色。
- 切换皮肤不刷新页面、不丢失播放位置和标注选区。
- 所有图表、波形、Minimap、画布、标签颜色都从 Token 读取。

### 19.2 多语言设计

平台必须支持国际化，首批建议：

- 简体中文 `zh-CN`
- 英文 `en-US`

可扩展：

- 繁体中文 `zh-TW`
- 日文 `ja-JP`
- 韩文 `ko-KR`
- 泰文 `th-TH`

国际化要求：

- 所有 UI 文案使用 i18n key，不在组件内硬编码。
- 时间、日期、数字、货币、百分比按 locale 格式化。
- 标签名、质检项、业务事件、单据类型支持项目级翻译。
- 快捷键说明、错误提示、Agent 解释、评测报告支持多语言。
- ASR 文本语言和 UI 语言解耦，允许中文 UI 查看英文录音转写。
- 后端返回错误码和结构化参数，前端负责本地化展示。

### 19.3 动效设计

动效用于帮助用户理解状态变化，不做无意义装饰。

核心动效场景：

- 页面切换：保持上下文的轻量过渡。
- 列表展开：树形聚合节点展开和收起。
- Minimap：当前播放线、精修窗口拖拽、串音连线高亮。
- 波形调听：播放指针、选区拖拽、A-B 循环区域。
- 画布节点：任务运行、失败、等待人工、重跑。
- Agent 建议：低置信、冲突、推荐关联的渐进式出现。
- 单据关联：拖拽关联、字段高亮、证据链连线。
- 数据回填：影响范围预估和执行进度。

动效约束：

- 尊重 `prefers-reduced-motion`。
- 关键操作反馈应在 100-200ms 内出现。
- 页面大切换不超过 300ms。
- 数据密集页面避免大面积动效。
- 播放器、标注、批量操作不能因动效阻塞。
- 所有动效必须有静态可理解状态。

### 19.4 粒子数据风

粒子风可以作为平台的高级视觉皮肤，但必须是数据驱动的语义表达。

适用场景：

- 首页洞察背景的轻量数据流。
- Agentic 任务 Trace 回放。
- 资产血缘流转。
- 全天时空音频 Minimap 的声音密度和异常聚集表达。
- 洞察大屏。
- 空状态和加载状态。

不适用场景：

- 标注表单。
- 高密度数据列表。
- 权限配置。
- 需要精确点击的波形编辑区域。
- 批量确认和删除等高风险操作。

粒子语义：

- 声音能量：粒子密度。
- 低置信：闪烁或脉冲，但频率必须克制。
- 串音：跨销售 / 设备泳道的粒子连线。
- Agent 推理：从证据点汇聚到建议点。
- 单据关联：从单据卡片流向对应音频片段。
- 资产血缘：从上游资产流向下游资产。

性能要求：

- 优先使用 Canvas 或 WebGL，不在 DOM 中渲染大量粒子。
- 粒子层必须可关闭。
- 低性能设备自动降级为静态线条和标记。
- 粒子层不参与核心点击命中，避免遮挡操作。

### 19.5 智能化交互

UI 需要具备智能化能力，但所有智能动作必须可解释、可撤销。

智能化能力：

- 根据用户角色推荐默认首页和默认聚合视图。
- 根据异常类型自动推荐数据列表展开路径。
- 发现同门店多设备重叠录音时，自动提示切换串音排查视图。
- 根据低置信、串音、单据缺失、标签冲突自动排序待处理队列。
- 在调听页自动高亮相关 ASR、标签、单据字段和事件证据。
- 在数据资产页自动推荐回填范围和影响下游。
- 根据用户历史操作推荐常用标签、常用筛选和快捷动作。

智能化交互必须展示：

- 推荐原因
- 证据来源
- 置信度
- 影响范围
- 是否会写入数据
- 可撤销入口

## 22. 当前 UI 原型图设计补齐

本节基于当前可点击原型 `prototype/auris-flow-ui` 补齐原型图设计说明。它不是新增信息架构，而是把前文的产品设计落到具体页面、具体组件、具体点击状态和可验收交互上。

### 22.1 原型目标

当前原型用于验证四条核心链路：

1. 从运营首页发现异常，进入数据、任务或调听。
2. 在任务配置工作台中配置任务类型、画布版本、当前任务版本的输入、处理、输出、控制节点，并映射到底层执行计划。
3. 在数据管理中按照时间、空间、事件、人物进行多层聚合，定位音频、单据和事件关联对象。
4. 在调听证据工作台中完成简单调听、证据审查、串音矩阵、标签标注、事件关联和 Agent 建议复核。

原型需要让用户一眼看出：

- 当前在处理哪个租户、项目、门店、日期、模型版本和标签版本。
- 当前页面解决什么问题。
- 当前异常如何关联到音频、人物、事件、标签和单据。
- 哪些动作只是修改当前任务草稿，哪些动作会发布版本或写入资产。
- Agent 推荐为什么出现、证据是什么、置信度是多少、人工如何接受或拒绝。

```text
│ 左侧主导航   │ 页面标题 + Tabs + 指标卡 + 主工作区 + 右侧抽屉       │

│ 资产         │                                               │
│ 设置         │                                               │
└──────────────┴───────────────────────────────────────────────┘
```

全局框架交互规则：

- 左侧导航切换页面时保留顶部上下文。
- 页面 Tabs 只切换当前页面内部视图，不重置租户和项目。
- 指标卡用于解释当前页面的状态，不作为装饰卡片。
- 右侧抽屉只展示当前选中对象的详情、证据、配置或动作。
- 搜索、筛选、导出保留统一入口，后续实现时按页面域加载不同条件。

### 22.4 P4 任务配置工作台原型图

当前原型优于早期设计稿，应作为任务配置页的交互基准。原因是早期设计稿把“画布”当作并列资源，容易把数据管理、项目管理和任务编排混在一起；当前原型把页面收敛为“任务配置工作台”，更符合真实使用方式：一个任务类型可以绑定多个画布版本，不同画布版本分别用于生产、灰度、影子评测、热修复和 A/B 实验。

任务配置不是通用流程图工具，而是“当前任务类型 + 当前任务版本草稿”的可视化配置器。

页面结构：

```text
┌────────────────────────────────────────────────────────────────────┐
│ 任务配置 / 登录风险复核                                            │
│ 任务类型：主体解析映射流 / 音频智能处理流 / 事件入库 / 复核导出       │
│ Tabs：流程配置 / 流程模板 / 编排版本 / 输入输出 / 调度设置 /           │
│       A/B 实验 / 运行记录 / 版本发布                                │
├────────────────────────────────────────────────────────────────────┤
│ 当前任务指标：任务版本 / 输入引用 / 触发方式 / 最近运行 / 发布状态     │
├──────────────┬──────────────────────────────────────┬──────────────┤
│ 任务类型列表  │ 阶段化画布                             │ 节点配置抽屉 │
│ 画布版本列表  │ 当前阶段相关节点 + 动态连线              │ 概览/映射/计划│
│ A/B 流量      │ 添加节点 / 生成建议 / 校验 / 运行一次     │ 运行/服务接入 │
├──────────────┴──────────────────────────────────────┴──────────────┤
│ 执行绑定 / 输出资产 / 外部回写 / 兼容性检查                           │
└────────────────────────────────────────────────────────────────────┘
```

核心概念：

- 任务类型：稳定的业务意图，例如“登录风险复核”“平台主体同步”“音频 URL 拉取”“复核导出”。
- 画布版本：任务类型下的可发布编排版本，例如生产主线、灰度候选、影子评测、热修复。
- 任务版本：一次可运行、可回滚、可审计的发布快照，固化当前画布、模型版本、标签版本、调度、输出契约和 Dagster 映射。
- 阶段：把复杂任务拆成可理解的步骤，例如输入引用、主体映射、音频模型链、策略判断、人工复核、资产导出回写。
- 节点：输入引用、处理步骤、模型服务、Agent、控制网关、输出资产、外部回写。

任务类型画布管理：

- 同一个任务类型允许多个画布版本并存。
- 生产主线可执行真实写入；灰度候选按比例分流；影子画布只计算指标不写业务结果；热修复画布用于小范围修复。
- A/B 实验必须显示流量比例、实验对象、回滚策略、关键指标和发布阻断。
- 画布版本发布后生成 Dagster Job / Asset Graph 快照，后续运行引用快照，不直接编辑历史版本。

流程配置交互：

- 默认进入“流程配置”，画布只展示当前阶段相关节点，避免所有节点挤在一屏。
- 点击任务类型或阶段后，画布、指标卡和右侧抽屉同步更新。
- 节点可拖拽，拖拽后连线实时跟随；拖动只修改当前任务草稿，不影响已发布版本。
- 点击节点，右侧抽屉展示节点概览、映射/字段、执行计划、运行记录和服务接入。
- 点击“添加节点”必须先打开节点库，再配置节点名称、节点类型、输入、输出、依赖、Dagster Op、Asset Key、IO Manager、幂等键和失败策略，最后才能添加到当前任务草稿。
- 点击“生成映射建议”必须创建异步 Agent 任务，展示建议进度、证据来源、置信度、可接受/修改/拒绝动作，不能只是按钮点击无反馈。
- 点击“校验兼容性”必须检查输入输出 Schema、资产依赖、模型服务版本、标签版本、权限、调度冲突和回写幂等。

输入和无数据状态：

- 没有项目数据时，不应该让用户直接新建“空数据资产”。
- 空状态主动作应是“通过连接器导入数据”，进入 CRM、API、S3/OBS、PBX、DMS、文件上传等连接器配置。
- 数据源接入后形成输入引用节点，再由任务类型画布选择是否消费这些引用。
- 一个数据源可以被多个任务类型画布引用；一个任务类型画布也可以消费多个数据源。

调度设置：

- “设置定时”配置的是当前任务版本的触发策略，不是配置画布本身。
- 必填项包括触发方式、时间表达式、分区范围、并发限制、重试策略、失败告警、依赖任务、是否允许补跑、是否跟随发布版本。
- 调度页必须显示下一次运行时间、最近一次运行、当前发布版本、候选版本是否会接管调度。
- “运行一次”是手动触发当前草稿或已发布版本；“发布版本”是生成可被调度引用的快照；两者不能混淆。

输出资产和外部回写：

- 输出节点必须明确区分“平台内部资产”和“外部系统回写”。
- 内部资产包括 `transcript_asset`、`speaker_turns`、`review_queue`、`evidence_package`、`processed_wav_asset`。
- 外部回写包括处理后的 WAV 上传 OBS / S3 后回传 URL、标签结果回调、复核结论回调、证据包导出、告警队列写入。
- 回写配置必须包含 Endpoint、鉴权、请求体映射、幂等键、重试策略、失败队列和运行记录。

模型服务节点：

- VAD、ASR、Diarization、Tagger 等节点在任务类型画布中只绑定服务版本和输入输出契约。
- 服务地址、鉴权、并发、超时、降级模型在“设置 / 模型配置”中统一管理。
- ASR 节点输出转写资产；Diarization 节点输出说话人轨；说话人转写视图是派生结果，不在 ASR 服务里混做。

节点详情抽屉字段：

- 节点概览：类型、职责、置信度、说明、影响范围、版本。
- 映射/字段：AI 建议映射、字段来源、目标字段、置信度、确认状态。
- 执行计划：任务定义、输出资产、处理步骤、触发方式、运行范围。
- 服务接入：服务版本、输入契约、输出契约、降级策略、调用权限。
- 运行记录：触发、执行、输出、回写四个阶段状态。
- 底层 Dagster 映射：Definition、Job、Op、Asset Key、IO Manager、Partition、Deps。

验收标准：

- 用户能看懂“这是当前任务版本草稿，不是在改全局数据源”。
- 用户能从任务类型进入不同画布版本，并理解生产、灰度、影子、热修复的差别。
- 新增节点必须先配置再添加，添加后右侧抽屉显示底层映射。
- 拖动节点时节点位置和连线同步变化，画布不裁切、不遮挡底部配置条。
- 生成建议、校验兼容性、设置定时、运行一次、发布版本、同步输出资产都必须有明确反馈和结果页。
- 发布版本、运行一次、设置定时、外部回写是不同动作，UI 不应混淆。

### 22.5 P5 数据管理原型图

数据管理页的核心不是音频列表，而是可变聚合路径。

页面结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 数据管理 / 多维聚合                                          │
│ Tabs：音频数据 / 人物声纹 / 事件 / 业务单据 / 关联视图          │
├──────────────────────────────────────────────────────────────┤
│ 指标：音频片段 / 客户组 / 事件关联 / 串音候选                  │
├──────────────────────────────┬───────────────────────────────┤
│ 聚合树                        │ 叶子对象详情                   │
│ L1 时间/空间/事件/人物         │ 当前对象 ID、路径、置信度        │
│ L2 时间/空间/事件/人物         │ 音频、标签、关联单据             │
│ L3 时间/空间/事件/人物         │ 进入调听、加入上下文篮           │
└──────────────────────────────┴───────────────────────────────┘
```

聚合维度：

- 时间：日期、小时、接待窗、片段。
- 空间：区域、门店、楼层、设备、试驾车。
- 事件：接待、试驾、报价、异议、成交、交付、售后。
- 人物：销售、客户组、声纹簇、质检员。

交互规则：

- 用户可以调整聚合顺序，例如 `空间 -> 时间 -> 事件` 或 `事件 -> 人物 -> 时间`。
- 每一层使用文件夹式展开，叶子对象是音频片段、业务事件或单据关联。
- 点击叶子对象只选中详情，不立即跳页。
- 点击“进入调听”才带上下文进入调听页。
- 右侧详情必须展示该对象的聚合路径，让用户知道它是如何被筛出来的。
- Agent 可以推荐聚合路径，但必须展示推荐原因。

验收标准：

- 数据列表不能退化成平铺表格。
- 用户可以通过时间、空间、事件、人物任一维度开始查找。
- 单据和音频在同一详情区出现，且可以进入调听验证。

### 22.6 P6 简单调听原型图

简单调听页用于快速完成基础复听和轻量标注，不承担复杂证据审查。

页面结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 简单调听                                                     │
├──────────────┬────────────────────────────────┬─────────────┤
│ 标签库/说话人 │ 波形 + ASR 对话流 + 标签高亮     │ 当前实体详情 │
│ 坐席/销售/客户│ 播放、倍率、跳转、标签 Chip       │ 标签编辑     │
└──────────────┴────────────────────────────────┴─────────────┘
```

关键交互：

- 默认左侧是坐席、销售、客户、展厅麦、串入声等说话人角色。
- 用户可以把当前 ASR 片段标为左声道、右声道或双声道。
- 用户可以直接修改说话人，修改后 ASR 片段、右侧详情和标签建议同步变化。
- 标签以 Chip 方式高亮在 ASR 中，用户可以添加或移除。
- 点击“进入证据审查”带当前片段、标签、说话人和时间点进入 P7。

验收标准：

- 页面比证据审查更轻，不出现复杂 Minimap 和矩阵。
- 说话人标注必须能左右声道切换。
- 标签修改必须在当前片段内可见。

### 22.7 P7 证据审查原型图

证据审查是当前调听工作台的核心页面，用于完成串音、单据、标签和 Agent 建议的综合判断。

页面结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 证据审查                                                     │
├──────────────┬────────────────────────────────┬─────────────┤
│ 复核队列      │ 工具条 / 设备栏 / Minimap        │ Agent/单据   │
│ 全量/低置信   │ 片段岛 / 波形 / 标签轨 / ASR Diff │ 字段差异      │
└──────────────┴────────────────────────────────┴─────────────┘
```

Minimap 必须表达：

- 同一天、同门店、不同销售、不同设备的完整录音分布。
- 当前窗口、当前播放点、当前复核片段。
- 主录音、串音候选、重复收录、缺失录音。
- 单据事件和音频事件的关联线。
- 关联置信度和人工可调整的连接关系。

标签轨必须表达：

- VAD。
- 说话人。
- ASR 分段。
- 实体标签。
- 意图标签。
- 质检标签。
- 单据事件。
- 串音证据。
- Agent 动作。

标签轨交互：

- 每个轨道可隐藏和恢复。
- 新增标签层必须选择 L1-L9 之一，不能无约束创建。
- 标签块可以拖动开始和结束时间。
- 标签块重叠时自动分层，不能互相遮挡。
- 控制 Chip 可以把当前 Segment 标注到指定轨道。
- 点击标签块的删除按钮只隐藏该标签，不删除底层模型结果。
- 新增标签后必须立即出现在对应轨道中。

事件关联交互：

- 单据事件、报价事件、试驾事件、试驾预约事件必须作为轨道对象出现。
- 点击事件块，右侧展示 ASR 证据、单据字段、关联置信度、来源模型和人工确认状态。
- 用户可以调整音频事件和单据事件之间的关联线。
- 用户可以接受 Agent 建议、拒绝建议或转人工仲裁。

右侧 Agent 面板必须展示：

- 建议结论。
- 置信度。
- 证据来源。
- 影响字段。
- 关联单据。
- 接受、拒绝、转人工。

验收标准：

- 用户能在一屏内看到 Minimap、当前波形、标签轨、ASR、单据和 Agent 建议。
- 标签轨不是静态展示，必须能增删、隐藏、拖动、分层。
- 单据事件和音频事件是可交互关联，而不是普通附件。

### 22.8 P8 串音矩阵原型图

串音矩阵用于从全天视角定位同一时间和空间内的多设备重叠录音。

页面结构：

```text
┌──────────────────────────────────────────────────────────────┐
│ 串音矩阵                                                     │
├──────────────────────────────────────────────┬───────────────┤
│ 时间 × 销售/设备矩阵                         │ 串音证据链     │
│ 行：销售工牌、展厅麦、试驾车设备、电话录音     │ ASR/设备/单据   │
│ 列：小时或接待窗                              │ Agent 推荐路径  │
└──────────────────────────────────────────────┴───────────────┘
```

矩阵单元状态：

- 正常录音。
- 重叠录音。
- 串音候选。
- 缺失录音。
- 主录音候选。
- 已确认。
- 跳过。

交互：

- 点击矩阵单元，右侧展示该时间窗所有设备的证据链。
- 点击“返回证据审查”，进入 P7 并定位到对应 Minimap 窗口。
- 点击“标记主录音”或“标记串音”，状态同步回证据审查。
- Agent 推荐路径必须说明从门店、时间窗、多设备重叠到主录音候选的推理过程。

验收标准：

- 页面不能只是一组色块，必须能看出哪个时间、哪个设备、为什么异常。
- 串音证据必须包含设备、ASR、能量、单据或事件中的至少两类信号。

### 22.9 P9 到 P13 支撑页面原型要求

标签管理：

- 展示 L1-L9 层级、类目、典型标签和当前版本。
- 冲突列表必须能回到证据审查。
- 发布版本必须展示影响资产和阻断原因。

业务洞察：

- 趋势图支持标签热度、模型质量、资产生成三种口径切换。
- 每个洞察结论都可以下钻到证据样本。
- Agent 建议必须带原因和动作。

评测中心：

- 模型对比必须展示能力、版本、变化和是否阻断。
- badcase 必须能回到音频证据。
- 回流建议不能直接自动发布模型。

数据资产：

- 资产目录展示资产状态、版本和质量分。
- 资产血缘展示上游依赖和下游影响。
- 数据回填必须展示范围、影响下游和审批状态。

设置：

- 模型链路、工具注册、阈值、权限必须项目级可见。
- 高风险动作必须展示 Policy Guard。
- 工具注册表需要展示 Schema、超时、权限、副作用和成本估算。

### 22.10 原型动效与智能视觉补齐

当前原型优先保证密度和可读性，动效只服务状态变化。

必须补齐的动效：

- 画布节点拖拽：节点提升层级、连线实时跟随、释放后吸附到网格。
- Minimap：播放线移动、当前窗口拖动、串音连线高亮。
- 标签轨：拖动开始/结束时间时实时显示时间范围，重叠时自动分层。
- Agent 建议：接受、拒绝、转人工后状态明确变化。
- 数据树：展开和收起时保持当前位置，不跳动。
- 页面配置：抽屉打开和关闭不影响播放点。

粒子风只在以下场景使用：

- Agent Trace 回放。
- 资产血缘和影响范围。
- Minimap 异常聚集。
- 空状态引导。

粒子风不得覆盖：

- 播放按钮。
- 标签拖拽手柄。
- 接受/拒绝按钮。
- 删除或隐藏按钮。
- 单据字段。

### 22.11 原型验收清单

原型进入下一轮视觉或开发前，至少满足：

- P4 任务类型画布节点可拖拽，连线跟随，新增节点可配置。
- P4 原始节点和新增节点都能展示底层执行映射。
- P5 数据管理能调整时间、空间、事件、人物聚合顺序并展开到叶子对象。
- P6 简单调听能修改说话人和声道。
- P7 证据审查能隐藏轨道、创建 L 层级标签、拖动标签块、展示重叠分层。
- P7 单据事件进入轨道，并与音频事件可关联。
- P8 串音矩阵能选择单元并回到证据审查。
- 所有智能建议都展示原因、证据、置信度、影响范围和人工动作。
- 浅色、深色、高对比皮肤切换时核心文本不溢出。
- 中文和英文语言切换时按钮和 Chip 不挤压关键操作。

## 23. 当前原型对齐与交互契约

当前原型已经覆盖运营首页、租户、项目、任务配置、数据管理、知识库、调听工作台、标签生产治理台、业务洞察、评测中心、数据资产和设置。后续 UI 设计以 `当前原型评审与优化计划.md` 为最新基线。

### 23.1 全局点击语义

所有点击必须明确属于以下类型之一。

| 类型 | 页面行为 | UI 要求 |
| --- | --- | --- |
| 聚焦 | 不跳模块，只更新当前选中对象、右侧详情、图表高亮 | 卡片、图例、趋势点、证据片段默认都应如此 |
| 下钻 | 进入另一个模块或详情页 | 按钮必须写清目标，例如“下钻证据”“查看资产血缘” |
| 生成候选 | 生成 Agent 建议、标签候选、Prompt 候选、运行草稿 | 只能写候选，不覆盖线上 |
| 人工修改 | 保存说话人、标签、Prompt、规则、候选修正 | 必须展示修改前后和保存状态 |
| 写回 / 回填 | 写入资产或外部平台 | 必须展示影响范围、审批和结果 |
| 发布 | 发布标签、Prompt、任务或配置版本 | 必须经过门禁和可回滚检查 |
| 诊断 | 展示 Trace、RunRequest、AssetCheck、执行映射 | 默认收在高级区，不作为业务主视觉 |

普通指标卡、洞察卡、资产卡和候选卡不得隐式跳转。需要跳转时，必须提供明确动作按钮。

### 23.2 顶部上下文栏

顶部上下文栏必须支持真实交互，而不是静态筛选展示。

最低要求：

- 租户、项目、门店、日期、模型版本、标签版本点击后可选择或弹出说明。
- 切换上下文后，当前页面的队列、资产、标签、评测和洞察口径同步变化。
- 无法真实切换时，也必须给出本地原型反馈，例如状态提示、上下文 chip 变化或 action feedback。
- 主题、语言、通知、账号入口的按钮尺寸和样式必须统一。

### 23.3 调听工作台 UI 基线

调听工作台包含三种模式：

1. 简单调听；
2. 证据审查；
3. 串音矩阵。

三种模式必须共享同一个会话上下文和证据对象。

UI 要求：

- 简单调听采用类聊天布局，左侧默认坐席 / 销售，右侧客户。
- 说话人标注支持 spk、角色、声道、置信度和来源设备。
- 音乐、噪音、静音、串音等非语义标签必须可见。
- 标签 chip 不能被隐藏或遮挡，内容过长时使用分组、换行或 tooltip。
- 证据审查的标签轨支持隐藏、创建、拖动、边界调整、重叠自动分层。
- 单据事件必须进入 Minimap 和标签轨，并和 ASR 句子、字段差异联动。
- 串音矩阵点击单元时，右侧必须展示证据链和可执行动作。

### 23.4 标签生产治理台 UI 基线

标签管理不再只是标签列表，而是标签优化闭环台。

首屏必须展示：

- 本轮输入；
- Agent 提升；
- 人工修改；
- 效果评价；
- 自动化等级；
- 执行 / 回写；
- 发布 / 回流。

标签层级固定为：

标签域 -> 标签组 -> 标签 -> 标签值 / 动作

候选标签必须展示：

- 证据句；
- Prompt 版本；
- 模型版本；
- 标签版本；
- Trace；
- 置信度；
- 冲突原因；
- 人审状态；
- 影响资产。

效果评价和发布门禁必须共享同一个运行详情，不允许在两个 tab 中生成不同口径的数据。

### 23.5 任务配置 UI 基线

任务配置的主对象是“数据流程”，不是技术画布。

页面主语言：

- 输入数据；
- 处理步骤；
- 模型服务；
- 输出资产；
- 调度策略；
- A/B 实验；
- 运行记录；
- 回写配置。

技术映射只在诊断层展示：

- JobDefinition；
- AssetSelection；
- PartitionsDefinition；
- RunRequest；
- AssetMaterialization；
- AssetCheck；
- run tags。

新增节点必须可以配置输入、处理、输出和底层执行映射。节点拖拽时，连线必须跟随节点移动。

### 23.6 数据资产 UI 基线

数据资产模块应以图表达血缘，不以列表替代血缘。

资产血缘页默认展示图，节点类型包括：

- SourceAsset；
- Asset；
- AssetCheck；
- Backfill；
- Human Loop；
- External Callback；
- Report / Insight。

资产详情、血缘、回填、质量和资产任务必须共享当前资产上下文。重复面板应合并或下沉，避免一屏出现多套相似说明。

### 23.7 业务洞察 UI 基线

业务洞察必须回答三个问题：

1. 哪个指标变了？
2. 为什么变？
3. 下钻到哪些证据和动作？

趋势图、桑吉图、雷达图、漏斗图和报告列表应服务不同 tab，不能只是换标题复用同一套图。

趋势图点击规则：

- 点击图例：聚焦该指标；
- 点击点：聚焦该日期证据；
- 点击事件标记：解释事件影响；
- 点击“下钻证据”：才进入调听、标签或资产模块。

### 23.8 设置 UI 基线

设置页需要区分不同配置对象：

- 模型配置：Audio Intelligence Service、Tagger、LLM、Embedding 的 provider、版本、路由、降级策略；
- 工具配置：工具 Schema、超时、权限、副作用、成本；
- 阈值配置：低置信、串音、标签、门禁、回填审批阈值；
- 权限配置：角色、租户、项目、数据范围、审批；
- 存储配置：OBS / S3、保留周期、脱敏、导出权限；
- 通知配置：渠道、模板、订阅和告警。

账号入口应提供类似 ChatGPT 的用户菜单，并支持账号设置模态框、租户 / 项目上下文查看和退出登录反馈。

### 23.9 视觉与布局验收补充

后续每次原型迭代必须检查：

- 1440x1024 下无横向溢出；
- 任何卡片、抽屉、弹窗不遮挡主操作；
- tab 内容不能串行成一行后挤压；
- 滚动条在内容超出时可见；
- 按钮高度、圆角、边框、颜色和禁用态一致；
- 浅色主题下核心信息对比度足够；
- 深色和高对比主题下状态色不只依赖颜色，需要有文字或图标；
- 所有按钮点击都有状态反馈；
- 空状态必须说明原因和下一步动作。

### 23.10 当前原型到后端 API 的交互契约

当前 React 原型后续应从 mock data 逐步切换到 BFF API。前端只依赖 FastAPI BFF，不直接访问 MySQL、Qdrant、对象存储或 Dagster。BFF 负责把后端复杂对象投影成当前页面需要的数据结构。

#### 23.10.1 通用 API 规则

- 所有接口使用 `/api/v1/*`。
- 列表接口支持分页、筛选、排序和搜索。
- 写操作必须返回 `status`、`trace_id`、`affected_objects` 和可见下一步动作。
- 异步动作返回运行对象 ID，例如 `task_run_id`、`agent_run_id`、`eval_run_id`、`export_job_id`。
- 错误统一映射到前端状态：`pending`、`success`、`failed`、`retry`、`blocked`。
- Qdrant 只在后端使用；前端看到的是“知识命中、相似证据、标签候选、召回解释”，不是 collection 或 vector。

#### 23.10.2 模块数据契约

首页：

- API：`GET /api/v1/insights/ops-summary`、`GET /api/v1/human-review-tasks`、`GET /api/v1/data-assets/recent`。
- 数据：待办、异常、运行概览、最近资产、趋势入口。
- 交互：点击卡片聚焦或下钻，处理后追加操作记录。

租户 / 项目：

- API：`GET /api/v1/tenants`、`GET /api/v1/projects`、`PATCH /api/v1/projects/{id}`。
- 数据：隔离上下文、配额、成员、审计、项目质量目标、ASR 数据拉取状态。
- 交互：新建、授权、配额调整、ASR 拉取必须有 pending、success、failed 和审计回执。

任务配置：

- API：`GET /api/v1/task-types`、`GET /api/v1/task-versions`、`POST /api/v1/task-runs`、`POST /api/v1/task-versions/{id}/publish`。
- 数据：任务类型、画布版本、任务版本、调度、AB、输入输出、执行映射、运行记录、输出回写。
- 交互：添加节点、生成建议、校验兼容性、运行一次、设置定时、保存草稿、发布版本都必须返回运行状态和记录。

数据管理：

- API：`GET /api/v1/audio-sessions`、`GET /api/v1/audio-sessions/aggregations`、`GET /api/v1/voiceprints`、`GET /api/v1/event-links`。
- 数据：聚合路径、音频、人物声纹、事件、业务单据、关联视图。
- 交互：维度切换只更新当前聚合；进入调听必须携带对象 ID、时间窗和证据上下文。

知识库：

- API：`GET /api/v1/knowledge-sources`、`POST /api/v1/knowledge-sources/{id}/sync-runs`、`POST /api/v1/knowledge-indexes/{id}/build-runs`、`GET /api/v1/knowledge-indexes/{id}/effects`。
- 数据：知识源、切片、索引、质量门禁、消费路径、效果漏斗。
- 交互：测试连接、同步一次、构建索引、运行质量检测、导出效果报告必须有异步状态。召回结果来自 BFF，前端不直接感知 Qdrant。

调听：

- API：`GET /api/v1/audio-sessions/{id}`、`PATCH /api/v1/conversation-boundaries/{id}`、`POST /api/v1/evidence-packs`、`POST /api/v1/human-review-tasks/{id}/decisions`。
- 数据：会话、边界、轨道、标签、单据事件、Agent 建议、人审动作。
- 交互：保存边界只记录完整对话开始/结束；标签轨、ASR、说话人、事件关联跟随边界重建，不在边界面单独偏移。

标签：

- API：`GET /api/v1/labels`、`GET /api/v1/label-versions`、`POST /api/v1/label-optimization-runs`、`POST /api/v1/label-versions/{id}/publish`。
- 数据：标签体系、候选、版本、冲突、发布门禁、Human Loop。
- 交互：候选只能进入草稿或人审，发布必须通过门禁。

洞察：

- API：`GET /api/v1/insights/metrics`、`GET /api/v1/insights/funnels`、`GET /api/v1/insights/reports`。
- 数据：趋势、桑吉、漏斗、雷达、报告、证据下钻。
- 交互：图表点击默认聚焦，跳转必须通过明确动作按钮；洞察解释可以使用 Qdrant 召回结果，但前端只接收解释和证据链接。

评测：

- API：`GET /api/v1/eval-runs`、`POST /api/v1/eval-runs`、`POST /api/v1/eval-runs/{id}/feedback-tasks`。
- 数据：评测集、运行、指标、badcase、回流。
- 交互：运行评测需要 pending、完成态、失败重试和 badcase 回流记录。

数据资产：

- API：`GET /api/v1/data-assets`、`GET /api/v1/data-assets/{id}/lineage`、`POST /api/v1/data-assets/{id}/backfills`、`POST /api/v1/exports`。
- 数据：资产目录、血缘、质量、回填、导出。
- 交互：血缘节点默认聚焦；回填和导出必须展示影响范围、审批状态、运行记录和失败分区。

设置：

- API：`GET /api/v1/settings`、`PATCH /api/v1/settings/{id}`、`POST /api/v1/settings/provider-tests`。
- 数据：模型服务、Provider、密钥引用、权限、策略、审计。
- 交互：服务连通性测试、配置校验、发布、退回和高风险策略修改都必须形成审计记录。

#### 23.10.3 前端验收

- 每个模块至少有一个列表接口、一个详情接口和一个动作接口对应当前原型。
- 所有动作按钮都能展示 pending、success、failed、retry 或 blocked。
- 空状态必须提供下一步动作，例如连接器导入、进入任务配置、创建人审任务。
- 前端不出现 ClickHouse、Qdrant collection、裸 Dagster UI 等后端实现细节。
- 所有下钻都携带 tenant_id、project_id、object_id、trace_id 和来源模块。
