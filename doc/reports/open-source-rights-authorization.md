# Open-Source Rights Authorization Record

Status: **BLOCKED — project owner confirmation and signature required**

This is the human authorization gate for an Auris Flow public release. An
automated check can prove that the Apache License 2.0 text is present; it cannot
prove that the repository has authority to grant those rights.

## Required release authorization

The project owner must complete every field below without placeholders:

- Legal name of the individual copyright and licensing-rights holder:
- Public copyright notice approved for `NOTICE`:
- Repository commit SHA reviewed:
- Intended release tag:
- Confirmation that the holder owns or is authorized to license all original
  contributions in the release candidate:
- Confirmation that third-party code, assets, fixtures, and public-dataset
  references have been reviewed against `THIRD_PARTY_NOTICES.md` and the release
  SBOM:
- Confirmation that no employer, client, contractor, or other person retains
  conflicting rights that prevent Apache-2.0 distribution:
- Approval date (UTC):
- Approver signature or verifiable approval reference:

## Acceptance rule

Until the completed record is committed or linked from an immutable release
approval, maintainers must not tag, publish, sign, or describe the repository as
a completed formal open-source release. The placeholder line in `NOTICE` must be
replaced with the approved notice in the same release candidate commit.

If ownership is shared or any contribution has a different rights holder, add a
separate signed authorization or provenance record for each holder before
release.
