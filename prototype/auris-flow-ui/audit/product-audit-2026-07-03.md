# Auris Flow 原型深度审计报告

日期：2026-07-03

范围：当前 React + TypeScript + Vite 中台原型，重点检查信息合理性、数据一致性、交互便捷性、展示重复、技术概念泄漏和视觉遮挡风险。

## 审计方法

- 本地构建：`npm run build` 通过，存在 Vite chunk 体积提示，但不是本轮交互问题。
- 视觉采集：用 Playwright 截取 12 个主模块和 10 个关键 tab 状态，共 22 张截图，位于 `audit/screenshots/`。
- 自动诊断：统计重复按钮、重复标题、明显技术词泄漏、大块空白风险，结果位于 `audit/capture-diagnostics.json`。
- Tab 相似度：对任务、数据、知识库、标签、洞察、设置做页面文本相似度检测，结果位于 `audit/tab-similarity.json`。
- 静态扫描：检查 `Dagster`、`DAG`、`mock`、`任务画布` 等用户已明确不希望暴露或容易误导的可见文案。

## 总体判断

当前原型已经不是“没有业务”的状态，主流程基本成型：租户/项目 -> 任务配置 -> 数据/知识/标签 -> 调听/评测 -> 洞察/资产/设置。但还存在三个根问题：

1. **平台对象边界没有完全收敛**：任务、数据资产、知识库、设置里都在展示“底层执行、资产映射、兼容字段”，导致业务用户会把它理解成工程编排平台，而不是质检/证据/知识运营平台。
2. **很多 tab 只是换标题，不是换任务**：洞察和设置最明显，页面壳和指标复用过多，用户会觉得“点击哪里都差不多”。
3. **新增知识库后缺少真正的知识表达**：知识可视化页现在更像数据表/路径面板，没有表达“source -> chunk -> entity/tag -> index -> app”的可视关系。

## P1：必须优先修正

### 1. 知识库的“知识可视化”没有真正可视化

证据：

- 截图：`audit/screenshots/18-knowledge-graph.png`
- 页面里有“当前数据视图”“知识可视化path”“清空 / 导出当前数据”等工作台式文案，但主区域没有清晰的知识图谱、流向图、实体关系或消费路径。
- 下方“知识消费路径”是文本条目，不足以支撑“可视化什么了”的用户问题。

建议：

- 保留现有 tab 和布局，不改模块结构。
- 将该 tab 的主体改成三段式可视图：
  - 左：知识源 `SOP / FAQ / 产品资料 / 标签样本 / 音频证据`
  - 中：知识对象 `chunk / entity / tag / rule / vector index`
  - 右：消费场景 `调听建议 / 标签召回 / 报告生成 / Agent 问答 / 任务回写`
- 节点之间必须有方向箭头、数量、质量状态、最近运行版本。
- “当前数据视图”这种表格语言应下沉为抽屉或底部明细，不作为知识可视化主表达。

### 2. 底层技术词泄漏过多，和产品定位冲突

证据：

- `src/App.tsx` 可见文案中仍有大量 `Dagster`、`DAG`、`mock`、`任务画布`：
  - 触发与调度附近：`Dagster 对象`、`ScheduleDefinition`、`RunRequest`、`SensorDefinition`
  - 版本发布附近：`发布 DAG 快照`、`当前编排 DAG`
  - 资产页：`Dagster Definition`、`Dagster 资产血缘图`
  - 标签/评测：`mock ledger`、`mock run record`
- 截图：`audit/screenshots/11-assets.png`、`12-settings.png`、`14-task-schedule.png`

判断：

- 底层确实可以是 Dagster，但前台不应该叫 Dagster 画布、DAG 快照、mock record。
- 对业务用户应叫“任务编排、执行计划、运行记录、资产血缘、调度对象、构建快照”。
- 如果需要给研发/实施看，可放到“高级执行映射 / 技术详情”折叠区。

### 3. 洞察模块 tab 内容重复，运营分析不成体系

证据：

- `audit/tab-similarity.json`：
  - 门店归因 vs 标签资产：0.816
  - 门店归因 vs 销售绩效：0.722
  - 门店归因 vs 模型质量：0.703
- 截图：`audit/screenshots/09-insights.png`、`21-insight-tag-assets.png`、`22-insight-reports.png`
- 用户连续指出“图表都一样”“没有曲线图/桑吉图/漏斗图/运营层数据”。

建议：

- 保留现有洞察模块和 tab，不重做信息架构。
- 每个 tab 必须有独立主任务：
  - 业务大盘：可配置指标看板，曲线 + 漏斗 + 待处理入口。
  - 门店归因：门店/时间/标签/业务动作的桑吉或路径归因。
  - 销售绩效：人员/门店转化漏斗和排名。
  - 标签资产：标签召回、命中、证据覆盖、资产回写。
  - 模型质量：ASR/VAD/说话人/标签模型质量雷达和趋势。
  - 报告中心：报告草稿、订阅、发送、回写记录。
- 顶部 KPI 可以保留，但每个 tab 的 KPI 维度要随当前 tab 变化，不能固定复制。

### 4. 设置模块 tab 高度同质化

证据：

- `audit/tab-similarity.json`：
  - 工具配置 vs 阈值配置：0.825
  - 工具配置 vs 权限配置：0.813
  - 阈值配置 vs 权限配置：0.813
  - 多个设置 tab 相似度接近或超过 0.8。

判断：

- 用户点开不同设置 tab，预期是不同配置对象。
- 现在更像同一个配置页换了标题。

建议：

- 不新增设置层级。
- 每个 tab 保留当前风格，但给出不同的对象表单：
  - 模型配置：Provider、模型版本、路由、降级策略。
  - 工具配置：ASR、VAD、Diar、Tagger、OBS 回写、平台回调。
  - 阈值配置：标签阈值、低置信、复核阈值、质量门禁。
  - 权限配置：角色、租户、项目、数据范围、操作审批。
  - 存储配置：OBS/S3、保留周期、脱敏、导出权限。
  - 通知配置：告警渠道、通知模板、订阅规则。

### 5. 任务“触发与调度”更像工程对象配置，不像任务配置

证据：

- 截图：`audit/screenshots/14-task-schedule.png`
- 页面直接展示 `ScheduleDefinition`、`RunRequest`、`SensorDefinition`、`BackfillPolicy`。

问题：

- 用户想配置的是“定时跑 / 事件触发 / 手动跑 / 回填 / 失败重试”。
- 底层对象名称应成为解释性技术字段，不应占据主视觉。

建议：

- 主面板改成业务调度卡片：
  - 触发方式：定时 / 事件 / 手动 / 数据到达 / 回填。
  - 生效范围：租户 / 门店 / 日期 / 分区。
  - 并发与重试：并发数、失败重试、跳过重复。
  - 当前状态：已启用、下次运行、最近成功、失败原因。
- 底部保留“高级执行映射”，折叠展示底层 Schedule/Sensor/RunRequest。

### 6. 调听工作台信息密度过高，文字和控件不便捷

证据：

- 截图：`audit/screenshots/07-listening.png`
- 自动诊断：重复按钮 `5`、`30`、`5s`、`确认关联`、`创建标注`、翻页箭头等。

问题：

- 同一屏同时出现队列、音频、minimap、轨道、标签、右侧 Agent、底部转写，信息很强但工作路径不聚焦。
- 小字号标签、轨道块、右侧建议文字容易看不清。

建议：

- 不改工作台结构，只做局部交互整理：
  - 顶部播放控制合并为“播放组 / 定位组 / 标注模式组”。
  - 标签层切换只保留一级 pill，二级标签改成可搜索下拉或最近使用。
  - 当前选中证据在右侧固定展示，轨道上只保留短标签。
  - 重复的 `5 / 30 / 5s` 改成带单位的按钮或 tooltip。

## P2：下一批修正

### 7. 资产模块混合了资产目录、底层兼容、质量、血缘

证据：

- 截图：`audit/screenshots/11-assets.png`
- 可见文案中有 `Dagster Definition`、`完整 DAG`、`Dagster 兼容性 20 项`。

建议：

- 资产页主语言改为“数据/证据/标签/报告资产”。
- 底层映射统一放入“执行映射”折叠区，不要在资产目录主路径露出。

### 8. 全局命令和局部按钮重复

证据：

- 数据模块重复 `筛选`、`导出`。
- 洞察模块重复 `标签资产`、`解释波动`、`生成报告`。
- 任务模块右侧 tab 和主 tab 都出现 `运行记录`。

建议：

- 全局按钮负责跨模块操作：搜索、筛选、导出。
- 局部按钮负责当前对象动作：同步、发布、运行、回写。
- 同名按钮需要加上下文，例如“导出当前资产”“导出页面报告”。

### 9. 数据/知识/资产之间的数量关系缺少解释

观察：

- 知识库展示知识对象 `12,846`、效果回写 `37`。
- 洞察展示标签样本 `37`、报告草稿 `4`。
- 资产展示多个 `4 / 1 / 46` 等数字。

问题：

- 数字可能都合理，但没有解释它们之间的统计口径。

建议：

- 每个关键数字旁边加口径说明：
  - 统计范围：租户 / 项目 / 日期 / 当前版本。
  - 对象类型：样本、资产、任务、报告、run。
  - 更新时间或来源资产。

### 10. 声纹页是强页面，但和浅色 Arco 风格略有割裂

证据：

- 截图：`audit/screenshots/16-data-voiceprint.png`

判断：

- 声纹数据已经正确关联到 wav、VAD、说话人、质量评分、向量维度，业务逻辑比之前好。
- 但“粒子风”如果过强，会和其他浅色中台卡片割裂。

建议：

- 保留声纹背景和播放感，但把中心大浮层移到侧边摘要。
- 背景表达向量维度、相似度、SNR、稳定性，主信息不遮挡波形/粒子图。

## P3：细节一致性

- “未保存 / 待同步 / 已保存”状态需要统一：状态徽标、按钮禁用、日志记录三处一致。
- “打开任务画布”建议改为“打开任务配置”或“打开编排视图”。
- “运行记录”如果同时是主 tab 和右侧 tab，需要明确一个是“任务运行记录”，一个是“当前节点运行记录”。
- 空态不能只是一大片留白，必须给出“为什么空、下一步做什么、从哪里导入/生成”。
- 列表里的重复实体名应减少视觉重复，例如音频文件名只在标题/详情出现一次，列表中保留短 ID。

## 数据对齐问题清单

| 对象 | 当前问题 | 建议口径 |
| --- | --- | --- |
| 租户 / 项目 / 门店 | 顶部上下文有，但模块内部分数字不说明是否继承上下文 | 每个 KPI 加 `当前租户/项目/门店/日期` 的小字口径 |
| 任务版本 / 编排版本 | `v3`、`v3.2.0`、`主线画布 v3`、`kb-index-v3.2` 并存 | 区分 `任务版本`、`编排版本`、`索引版本`，不要混写 |
| 数据资产 / 知识对象 | 数据资产和知识对象数量都大，但关系不明确 | 在知识库说明从哪些数据资产生成了多少 chunk / entity / index |
| 标签 / 洞察 | 标签样本 37 和洞察报告 37 容易被误认为同一数字 | 明确一个是样本数，一个是回写/报告数 |
| ASR / 声纹 / wav | 声纹页对齐较好 | 保持 wav -> VAD -> Diar -> voiceprint -> quality 的血缘链 |
| 回写 / 导出 | 平台回调、OBS URL、报告导出分散在任务/资产/知识/洞察 | 统一叫“输出通道”，并标明 sink 类型 |

## 建议产品故事线

这套原型最合理的用户故事不是“数据管理系统”，而是：

1. 运营或质检负责人在租户/项目上下文里配置任务。
2. 任务通过连接器接入平台数据、音频 URL、业务事件和单据。
3. 编排运行后生成音频分段、ASR、说话人、实体映射、标签候选和证据包。
4. 调听工作台处理低置信、金额冲突、申音候选等 Human Loop。
5. 标签和知识库把确认过的证据沉淀为可复用资产。
6. 洞察把标签资产转成业务指标、归因、漏斗、报告和回写动作。
7. 评测和设置控制模型、服务、阈值和质量门禁。

只要这个故事线稳定，页面里的复杂对象就不会显得散。

## 建议优先级

第一优先级：

- 修正知识库知识可视化。
- 清理前台 `Dagster / DAG / mock` 技术词。
- 拆分洞察 tab 的真实内容差异。

第二优先级：

- 重整任务触发与调度。
- 设置 tab 内容去同质化。
- 调听工作台做控件分组和文字可读性优化。

第三优先级：

- 数据口径说明。
- 全局/局部按钮命名去重。
- 声纹粒子视觉不遮挡主信息。
